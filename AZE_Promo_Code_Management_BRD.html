Promo Code & Package Management (Admin & Student Portals) — Business Requirement Document
Version: 2.0 • Date: 13/10/2026
Prepared For: AZE Platform Team
Prepared By: Zignuts Technolab Private Limited (India)

Current Business Problem

  • No Promo Code System Previously: Previously, the AZE platform had no system for promotional codes or discount coupons at all. Academic institutions, marketing campaigns, and trial evaluators had no automated way to receive discounted or promotional test access. Everything required manual account creation by tech teams or forced users to pay full retail price.
  • Lack of Self-Service Test Package Discounting: In the Student Portal's "Buy Tests" module, students purchasing test packages have no way to apply promotional discounts or claim scholarship waivers at checkout. Even when students receive institutional discount codes, they cannot apply them self-serve.
  • Friction and Confusion from Package Mismatch: When a student enters a valid promo code designated for a specific package while checking out a different package, standard platforms merely display an unhelpful "Invalid Code" error. Without an interactive pop-up guiding them to the correct package, students get frustrated, assume the code is broken, and abandon the checkout.
  • Manual Operational Overhead: Sales, academic coordinators, and operations staff spend excessive hours manually adjusting balances, setting up one-off test allocations, and resolving user complaints regarding promo code application.

The Proposed Solution

  • Complete End-to-End Promo Code System: Introduce a robust, automated promotional code engine across Super Admin, Student Portal, and Client Portal.
  • Dual-Tab Promo Code Architecture in Admin Portal:
    • Tab 1 — Test Promo Codes: Allows admins to create promo codes linked directly to one or more individual tests (100% test access) for direct student dashboard redemption.
    • Tab 2 — Package Promo Codes: Allows admins to create promo codes linked to specific test packages in the "Buy Tests" catalog, with configurable discount rules (Percentage Discount, Fixed Amount Reduction, or 100% Free Package Waiver).
  • Smart Package Mismatch Pop-Up with One-Click Redirection:
    • Embed an intuitive promo code input inside the Order Summary on the Student Checkout page (/student/package/:id).
    • If a student enters a code valid for a different package, the system automatically detects the target package and displays an interactive Pop-Up Modal informing the student that the code belongs to that package, featuring a direct button "Redirect to Correct Package →" that navigates the user to the correct package checkout with the promo code ready to apply.
    • If a 100% Free Package promo code is applied, the checkout automatically sets the total to $0.00, changes the CTA to "Claim Free Package", bypasses the payment gateway, and redirects the student to the Active Tests tab ready to begin.

Systems Impacted

  • AZE Super Admin Portal (https://azetest.ai/admin/dashboard): Pricing & Plans → Promo Codes module with 2 dedicated tabs (Test Promo Codes and Package Promo Codes), creation modal with configurable discount models (Percentage, Fixed, 100% Free), and Client Account quota override controls (number of tests & student account creation limits).
  • Student Web Portal (https://azetest.ai/student): Student Dashboard ("Redeem Promo Code" card) and Buy Tests Checkout screen (/student/package/:id) with promo code validation, dynamic pricing calculation, 100% free bypass, and smart package mismatch redirection pop-up.
  • Student Mobile Applications (Android & iOS): Native Dashboard "Redeem Promo Code" cards and Mobile Buy Tests checkout sheets with uppercase formatting, haptic feedback, and Active Tests redirection.

Assumptions & Dependencies

  • Test templates and test packages must already exist in the system catalog before being associated with promo codes.
  • A Package Promo Code can be mapped to one specific package or multiple eligible packages.
  • When a 100% Free Package promo code is applied, the transaction completes without invoking external payment processors (e.g., Stripe).
  • Student redemption limits are tracked per authenticated student account ID; client redemption limits are tracked per client organization ID.
  • Promo code strings are case-insensitive and whitespace-trimmed across all interfaces.

Business Requirements

Part A: Super Admin Portal (https://azetest.ai/admin/dashboard)

1. Module Structure & Dual-Tab Interface

  • Ability for administrators to access the Promo Codes module under Pricing and Plans → Promo Codes.
  • Ability for administrators to seamlessly switch between two dedicated tabs:
    • Tab 1: Test Promo Codes Direct Tests (Direct test assignment and instant dashboard redemption).
    • Tab 2: Package Promo Codes Packages (Package linkage with configurable discount and pricing rules).
  • Ability for administrators to view executive summary KPI cards at the top of each tab: Total Active Codes, Total Redemptions Claimed, Scheduled Campaigns, and Expired / Inactive Codes.
  • Ability to filter, search by code or test/package title, and toggle table density (Compact, Cozy, Comfortable) independently on both tabs.

2. Test Promo Code Creation (Tab 1 — Test Promo Codes)

  • Ability for administrators to enter a custom promo code string or click "Generate Random Code" to auto-generate a unique 8-character code.
  • Ability for administrators to select one or multiple tests from the available test catalog.
  • Ability for administrators to define campaign validity by configuring Valid From and Valid Until date and time.
  • Ability for administrators to set the Redemption Limit per User defining how many times an individual user can redeem the code (numeric stepper, default: 1).
  • Ability for administrators to set the Total Redemption Limit per Promo Code defining the maximum number of times the promo code can be redeemed in total across all users (numeric stepper, default: 1).
  • Ability for the system to automatically determine and display the promo code status (Scheduled, Active, Expired, Inactive) based on the current timestamp.

3. Package Promo Code Creation & Pricing Rules (Tab 2 — Package Promo Codes)

  • Ability for administrators to enter a custom promo code or generate one randomly.
  • Ability for administrators to assign one or multiple Test Packages from the package catalog (e.g., "Student Test Package", "4-Skill Comprehensive Package").
  • Ability for administrators to configure the Benefit / Discount Type:
    • 100% Free / Full Waiver: Waives 100% of the package cost, allowing students to claim the entire package for $0.00.
    • Percentage Discount (%): Deducts a configurable percentage (1% to 100%) from the package retail price (e.g., 20% off, 50% off).
    • Fixed Amount Discount ($): Deducts a flat currency amount from the total package price (e.g., $10.00 off).
  • Ability for administrators to configure validity start and end dates (Valid From, Valid Until).
  • Ability for administrators to set the Redemption Limit per User defining how many times an individual user can redeem the code (numeric stepper, default: 1).
  • Ability for administrators to set the Total Redemption Limit per Promo Code defining the maximum number of times the promo code can be redeemed in total across all users (numeric stepper, default: 1).
  • Ability for administrators to toggle campaign status between Active and Inactive at any time.
Part B: Student Portal (Web Portal & iOS / Android Mobile Apps)

4. Student Dashboard Direct Redemption

  • Ability for students to view a dedicated "Redeem Promo Code" card on their Dashboard placed directly below the "Get More Tests / Buy Tests" section.
  • Ability for students to enter an alphanumeric code with automatic uppercase conversion and whitespace trimming.
  • Ability for the system to validate the promo code upon clicking "Redeem":
    • If the code is a Test Promo Code or 100% Free Package Code: The system provisions the tests immediately, displays a celebration confirmation, and automatically redirects the student to https://dev.azetest.ai/student/my-test on the Active Test tab.
    • If the code is a Package Discount Code (partial discount): The system displays an informative message informing the student that the code provides a discount for [Package Name], with an instant button to navigate to that package's checkout page with the code pre-applied.

5. Buy Tests & Checkout Module Integration

  • Ability for students to browse test packages under Buy Tests and select a package to reach the Checkout screen (/student/package/:id).
  • Ability for students to view an "Apply Promo Code" section within the Order Summary panel on the Checkout screen.
  • Ability for students to enter a promo code and click "Apply".
  • Dynamic Price Recalculation:
    • When a valid percentage or fixed discount code is applied, the Order Summary immediately updates to show: Original Package Price, Applied Promo Code & Discount Amount (e.g., -$10.00), and Final Amount Payable.
  • 100% Free Package Claim Workflow:
    • When a 100% Free promo code is applied, the Total updates to $0.00.
    • The primary action button dynamically transforms from "Proceed to Payment" to "Claim Free Package" (or "Redeem Package").
    • Clicking "Claim Free Package" completes the transaction without opening payment gateways, provisions all package tests to the student, and redirects to https://dev.azetest.ai/student/my-test (Active Test tab).

6. Smart Package Mismatch Pop-Up & Redirection Button

💡 Interactive Redirection Pop-Up
When a user inputs a promo code that belongs to an alternative package, the system avoids dead-end error messages and triggers an interactive pop-up modal with an instant redirection button directly to the correct package checkout.
  • Ability for the system to detect when a student enters a valid promo code that belongs to a different package than the one currently selected in checkout.
  • Ability for the system to display an interactive Pop-Up Modal:
    • Modal Title: "Package Mismatch — Promo Code Available"
    • Modal Description: Clear notice explaining: "This promo code is valid for [Correct Package Name], not the current package."
    • Primary Action Button: [Redirect to Correct Package →] (or [Switch to {Correct Package Name}]).
    • Secondary Action Button: [Stay on Current Package].
  • Ability for the student to click the redirection button and be navigated immediately to the checkout screen of the correct package (/student/package/:target-id), with the promo code already pre-populated in the promo code field and ready for instant redemption.

7. User-Friendly Error States

  • Ability for the system to prevent double submission during redemption processing by showing a loading spinner and disabling the action button.
  • Ability to display clear, friendly error messages for invalid scenarios:
    • Code Expired: "This promo code expired on [Date]."
    • Code Not Active Yet: "This promo code is scheduled to become active on [Date]."
    • User Limit Exceeded: "You have already reached your maximum redemption limit for this promo code."
    • Global Limit Exceeded: "This promo code has reached its maximum total redemption limit across all users."
    • Invalid Code: "Invalid promo code. Please check the spelling and try again."
